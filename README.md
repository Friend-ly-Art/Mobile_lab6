# Лабораторная работа № 5

Тема: верстка мобильно-ориентированного приложения «Мои растения».
Продолжение интерфейса лабораторных № 2 и № 4.

## Что сделано

Четыре отдельных логических экрана: коллекция (index.html), карточка растения (plant.html), календарь ухода (calendar.html), профиль (profile.html). Ссылки меню открывают страницы, а не блоки-заглушки. У каждой карточки свой адрес вида plant.html?id=monstera.

- Структура css, js, assets; все изображения локальные, внешних шрифтов и CDN нет.
- Семантические header, main, nav, section, footer, а также article, form и dl.
- Базовый CSS-reset в css/reset.css.
- Flexbox для навигации, коллекции, карточки, календаря и кнопок.
- Mobile First: базовые стили для смартфона, media queries от 48rem (768px) и 75rem (1200px) при стандартном размере шрифта 16px.
- Размеры задаются преимущественно в rem и процентах, высота основного блока — в vh.
- До 768px: одна колонка. От 768px: две колонки и горизонтальная карточка. От 1200px: четыре колонки коллекции.
- Viewport записан точно по методичке. Для реального продукта лучше убрать maximum-scale=1.0 и user-scalable=no, чтобы сохранить масштабирование.
- Есть читаемые исходники src и минифицированная копия dist. Минификация выполнена; размеры до и после записаны в minification.json.

## Запуск

1. Распакуйте архив полностью.
2. Откройте src/index.html или dist/index.html в браузере.
3. Для стабильного localStorage между страницами рекомендуется открыть папку src через Live Server в VS Code. Альтернатива: в папке src выполните `python -m http.server 8000` и откройте http://localhost:8000.
4. В инструментах разработчика браузера переключайте размеры 390×844, 768×1024 и 1440×960.

Интернет и установка npm-пакетов для сайта не нужны. Поведение localStorage для адресов file:// зависит от браузера, поэтому проверяйте сохранение через localhost или HTTPS.

## Что работает

Поиск по названию, переход к выбранному растению, редактирование названия/комнаты/заметки/интервала полива, отметка полива, пересчёт следующей даты, отображение ближайших задач и изменение имени владельца. Данные сохраняются в localStorage под ключом my-plants-lab5-v1. Повторная отметка полива в тот же день заблокирована.

Расписание учебное: интервалы пользователь выбирает самостоятельно. Первые два растения при первом открытии требуют полива сегодня. После полива следующая дата вычисляется от текущей даты. При изменении интервала после полива дата пересчитывается от последней отметки; до первой отметки сохраняется исходная ближайшая дата.

Это учебный фронтенд: регистрации, сервера, добавления/удаления растений, загрузки фотографий и синхронизации между устройствами нет. Внешний вид и иллюстрация монстеры продолжают предыдущую работу.

## Повторная минификация

После изменения src запустите из папки lab5: `python build.py`.
Скрипт работает на стандартной библиотеке Python 3. Он удаляет комментарии и лишние пробелы в HTML/CSS; в JS удаляет блочные комментарии и отступы, сохраняя переносы строк. Это щадящая минификация без переименования переменных; минификатор рассчитан на эти исходники, не на произвольный сторонний JS.

## Что показать преподавателю

- Коллекцию, карточку и календарь на ширинах 390 и 1440px (минимум 6 снимков).
- Профиль как дополнительный четвёртый экран.
- CSS с Flexbox и двумя медиазапросами, структуру папок и viewport.
- Исходники src, минифицированные файлы dist и minification.json.
- Отметку полива, переход в календарь и сохранение после перезагрузки.

## Краткие ответы на контрольные вопросы

1. Мобильный UI/UX — читаемый текст, крупные области нажатия, короткие формы, понятная навигация и отсутствие горизонтальной прокрутки.
2. Различия исходного оформления браузеров уменьшают с помощью normalize.css или CSS-reset. Здесь сброшены отступы, задан box-sizing: border-box и наследование шрифта полями формы.
3. Mobile First — сначала базовые стили телефона, затем расширение макета на больших экранах через min-width.
4. Медиазапрос применяет CSS при выполнении условия. Например, `@media (min-width: 48rem)` включает две колонки коллекции.
5. Минификация — уменьшение объёма кода удалением необязательных пробелов, переносов и комментариев с сохранением поведения. Это не то же самое, что gzip-сжатие при передаче.
